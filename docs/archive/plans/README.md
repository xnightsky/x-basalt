# 内容级归档标准

> 本文定义正式文档整篇迁移与章节归档的准入，不只适用于计划。归档统一进入 `docs/archive/`，不是删除，也不自动证明当前实现或内容失效。

## 准入三问

三个问题都能有据回答，才执行归档：

1. **哪些内容已结束或被接替？** 计划的已授权执行范围结束且有验证记录；旧方案有接替文档；调研的原基线不再代表当前边界。日期或 `completed` 不单独作为依据，未核对的验收不得直接补勾。
2. **当前规则与未完成义务在哪里？** 当前实现契约、仍有效的决策理由、测试编号在 `design/`；使用方式在 `use/`；未完成/持续关注在根 `TODO.md`。调查收口不等于问题修复，系列计划可以按独立闭合阶段归档。
3. **证据与引用是否完整？** 原因、备选方案、旧读数与负结果完整保留；旧入口、相对路径及标题锚点可找到正确内容。唯一证据可以留在归档，不要求复制到活跃正文，更不因其唯一性强制把已结束计划留在活跃目录。

未获授权或未完成的执行范围、没有接替位置的当前义务、未验证的收口，先保留活跃并记录停点。

## 整篇归档

- 计划进入 `archive/plans/`，调研进入 `archive/research/`，旧设计/决策进入 `archive/decisions/`，保留日期与分类。
- 保留原正文与证据；必要引用重定位、脱敏、状态校准单独说明，不改写历史读数。
- 整篇设计被接替时标 `superseded_by` 指向当前设计；计划 `status` 表示原执行状态，不是兼容或可靠性认证。
- 归档理由、有效边界去向、未验证与风险记入本轮执行计划或文档归档注记。

## 局部归档

混合文档不整篇搬走，只摘出已结束执行记录、旧工具表/方案、实验与阶段快照：

- 按原文档/阶段形成少量归档记录，不把每段拆成一个文件。
- 归档写明来源文档、原章节、当时基线与当前接替位置；活跃文档保留历史链接与仍有效的简短理由。
- 当前契约、安全规则、有效 Decision Log 和测试编号不能因带日期一并移走；先核对它们已有当前承载位置。
- 摘出章节的入链同步指向归档，必要时保留原标题短指路；同时验证相对路径与标题锚点。
- 局部被接替不将仍有效的整篇标成失效；明确归档的是哪些章节。

## 验证与维护

1. 整理前保存文件/章节基线，核对整篇迁移和每个摘出段落完整保留。
2. 当前文档与历史观察分层；注明版本、数据集和验证边界，不用新版文档冒充新版 oracle 实测。
3. 根 TODO 的未完成/关注条目不因归档删除或隐藏；相关入口更新到当前契约和归档证据。
4. 只修本轮影响的引用，不顺带清理全部既有断链；无新增断链不代表旧链接全正确。
5. 新增/改动 `docs/` 后用本项目 CLI 补元数据；已有文档带 `--refresh-derived`，核对正文 hash。
6. Git 提交/推送仍须当前会话单独授权，归档规则不构成授权。
